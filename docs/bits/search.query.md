# search.query — A visitor searches the whole site

- **Trigger:** the search box (header button, ⌘K, Ctrl+K or `/` on any page; the "Search" item in the mobile menu), or the results page `/search?q=…` (Enter in the box, a shared link, the form on the page). Both call `GET /search?q=…` (optional `type`, one or more; `miles` 25/50/100; `limit` up to 30).
- **Who:** anyone.
- **Path:** box: `apps/app/src/components/search/site-search.tsx` → `browserApi` (`apps/app/src/lib/search.ts`, from the browser, no cookies). Page: `apps/app/src/app/search/page.tsx` → `getPublicApi()` (cached 5 minutes). Then `SearchController` → `SearchService` → `runSearch` (`apps/api/src/search/search.ts`): `parseQuery` (`query.ts`) reads the words, Spanish words, a kind of result, a town or ZIP code and pinned answers → each word corrected against `search_words` → full-text and trigram match on `search_documents` → closest places when a town or ZIP was named → the next edition of past events.
- **Data:** reads `search_documents` (events, places and clubs written by the triggers in migration 0008; guides, rules and services written by the API when it starts), `search_words`, `zip_codes`, the towns of `places` and `airports`, and `events` (next editions). Writes nothing. The box keeps the last 5 searches in the browser's `localStorage` (`servo.recent-searches`), never sent anywhere.
- **Rules:** only public things: events published and not rejected (the same rule as `events.list`), places, clubs and the site's content. Upcoming events rank above past ones; past ones are marked and point to their next edition. A town counts when it's the whole search or follows "near", "in" or "cerca de"; a ZIP code counts anywhere; then only what is within the radius shows, closest first (guides and rules stay; events, places and clubs without a place on the map don't). `partial` says no result has every word. Results are grouped (Events, Places, Clubs, Guides and rules), the group with the best result first. The results page is `noindex`. Cached 5 minutes; the words searched aren't logged.
- **Errors:** an empty or longer than 100 characters search answers 400. Nothing found answers an empty list: the page and the box offer This weekend, Near me, Can I fly here? and Send us your event. If the API doesn't answer, the page says search is taking a break and the box offers the results page.
- **Test:** `query.test.ts` (what a search means, runs in CI) and `golden.test.ts` (the 36 golden searches, none of them partial, plus tabs, the radius, next editions and the triggers, against a real database; needs the local database, skipped in CI).
- **Observe:** API log lines with `bit: "search.query"` and their time in `ms`.
- **Status:** verified — 2026-10-29 (box with keyboard and on a phone, results page, tabs, radius, "Can I fly here?" at a town)
